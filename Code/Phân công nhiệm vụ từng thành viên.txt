
Nội dung Công việc Của Từng Thành Viên

1. Hải (Network Core)
Nghiên cứu & Áp dụng: Nắm vững thư viện socket và threading trong Python.
Xử lý định tuyến (Routing): Viết một hàm "Dispatcher" (người điều phối) để phân loại các JSON packet gửi đến. Ví dụ: Nếu action == "LOGIN" thì đẩy vào hàm A, nếu action == "MOVE" thì đẩy vào hàm B.
Quản lý bộ nhớ & Lỗi mạng: Bắt các lỗi ConnectionResetError (do client rút mạng). Đảm bảo khi một Client rớt, phải xóa Socket đó khỏi danh sách để tránh Server bị crash hoặc tràn RAM (Memory Leak).
Đóng gói dữ liệu: Đảm bảo xử lý lỗi "dính gói tin" (TCP stream packet gián đoạn hoặc gộp chung) bằng cách quy định độ dài gói tin ở header hoặc dùng ký tự phân cách.

2. Vĩ (Game Logic & Timer) 
Thuật toán Caro: Viết hàm duyệt ma trận 2D hiệu quả (thường là ma trận 15x15 hoặc 20x20) để tìm chuỗi 5 quân liên tiếp. Phải tính đến luật chặn 2 đầu (tùy chọn theo yêu cầu nhóm).
Quản lý Vòng đời Room: Viết class Room quản lý trạng thái: WAITING (chờ người), PLAYING (đang chơi), FINISHED (đã xong).
Kiểm soát Luồng đếm giờ (A2): Viết một Timer (bằng Thread độc lập) đếm ngược 30s. Khi người chơi đánh một nước hợp lệ, phải có cơ chế Interrupt (ngắt) luồng Timer cũ ngay lập tức và tạo Timer mới cho đối thủ.
Trạng thái đồng bộ: Xử lý logic ghép Snapshot bàn cờ (mảng 2D) thành chuỗi để đẩy qua Hải gửi cho khán giả.

3. Q. Hào (Database Backend) 
Thiết kế Lược đồ (Schema): Tạo các bảng trên Supabase: Bảng Users (ID, Username, Password, Elo/Điểm), Bảng Matches (MatchID, Player1, Player2, Winner, Time).
Tích hợp API: Sử dụng thư viện supabase-py hoặc requests để tương tác với cơ sở dữ liệu từ Server Python.
Xử lý Bất đồng bộ (Async): Viết các hàm đẩy dữ liệu (Insert) lên DB theo luồng riêng (Thread) để Server không bị "đứng hình" (blocking) trong lúc chờ phản hồi từ Supabase.
Bảo mật cơ bản: Băm mật khẩu (Hashing) trước khi lưu vào cơ sở dữ liệu thay vì lưu plain text.

4. Nga (Client UI - Lobby)
Làm chủ Qt Designer: Học cách sử dụng phần mềm Qt Designer để kéo thả các Widget: QLineEdit (khung nhập), QPushButton (nút bấm), QListWidget (danh sách).
Thiết kế Layout: Sử dụng QVBoxLayout và QHBoxLayout để giao diện của Sảnh và Form đăng nhập tự động co giãn (Responsive) khi người dùng phóng to/thu nhỏ cửa sổ.
Liên kết UI với Network: Kết nối các tín hiệu (clicked.connect) từ nút bấm để gọi các hàm gửi dữ liệu mạng của S. Hào/Hải.
Trải nghiệm người dùng: Code các hộp thoại (QMessageBox) thông báo lỗi thân thiện (VD: "Sai mật khẩu", "Mất kết nối đến máy chủ").

5. Đạt (Client UI - Gameplay) 
Xây dựng lưới 2D: Sử dụng QGridLayout để sinh ra một ma trận các ô vuông. Tùy chỉnh CSS (QSS) cho các ô này để trông giống bàn cờ thực tế.
Xử lý Đa luồng trên Client: Khác với Server, UI của PyQt6 chạy trên luồng chính (Main Thread). Đạt phải biết dùng QThread và pyqtSignal để nhận dữ liệu mạng mà không làm đơ (Not Responding) giao diện game.
Hoạt ảnh & Giao diện động: Code logic cho thanh đếm ngược thời gian (QProgressBar) giảm dần mượt mà. Đổi màu hiển thị quân cờ X (đỏ) và O (xanh).
Phân quyền UI: Viết hàm khóa toàn bộ bàn cờ (setDisabled) khi đang là lượt của đối thủ hoặc khi người dùng là Khán giả.

6. S. Hào (QA & Integration) 
Chuẩn hóa Giao tiếp: Là người soạn thảo "Từ điển API" (File tài liệu liệt kê toàn bộ các gói tin JSON). Ví dụ: Thống nhất mọi file phải gọi key là "player_id" chứ không phải "id_player".
Quản lý Git & Xung đột: Hỗ trợ các thành viên khác khi họ bị Git Conflict. Chịu trách nhiệm duyệt Pull Request trước khi Merge code của cả team lại với nhau.
Kịch bản Kiểm thử (Test Cases): Viết script Python tự động (Automation Test). Ví dụ: Code 1 file bot tự động giả lập 20 người cùng gửi lệnh "Mời thách đấu" xem Server của Hải có bị sập không.
Kiểm thử Biên (Edge-case): Chủ động tìm các lỗ hổng logic. (VD: "Chuyện gì xảy ra nếu tôi đang bấm Join phòng thì mạng rớt?").
